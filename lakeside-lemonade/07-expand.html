Module 07 · Part 2 — Agents & systems

Why would a team of agents beat one?

Scenario
You're weighing a second stand across town. One agent can work it up — or several specialists can run in parallel and one can pull it together.
Your role
You decide the split: which workstreams run at once, and who synthesizes at the end.
What you'll practice
Running the same question two ways — one window versus parallel workstreams — and feeling the difference in how grounded the answer is.
Tool
Claude orchestrating sub-agents.

Don't know where to find it?
Reuse everything from Part 1 — the personas, the price, the cost sheet, the corner you picked. This is a new decision laid on top of it, not a fresh start.

Picture a hard operation. You could ask one general surgeon to do all of it — or bring in sub-specialists who each handle their part at the same time, while someone leads. A go/no-go on a second stand is the same shape: one agent digs up demand, one runs the numbers, one scouts the competition, one names what would make it fail — and one pulls it into a recommendation.

1One window, whole question

Open Claude, bring your Part 1 work back in, and ask the whole thing in one go:

Should I open a second lemonade stand, and where? Work up the whole analysis.

You'll get one coherent answer — demand, costs, competition, risks, a recommendation, all in a single pass. But each part gets only a slice of the attention. The numbers are thin because the window was also doing demand; the competition read is a sentence because it was also weighing risk.

2Split it, then synthesize

Now ask for the same decision as four focused passes that run in parallel, then one that reconciles them:

Run this as four parallel workstreams, each as its own focused pass: 1) demand — who'd buy at a second location, from my personas 2) costs — the real cost-per-cup and setup for a second stand 3) competition — who already sells there and at what price 4) risks — what would make this fail Then synthesize the four into a single go/no-go with the trade-offs, and note where the workstreams disagreed.

Each pass comes back with its full attention spent on one thing — and the synthesis has to hold all four at once, including the place where the demand read and the risk read pull in opposite directions. That disagreement is the part you most want to see.

The pattern

Fan-out-and-synthesize

Split the work into parallel specialist workstreams, then have one pass reconcile them. It's better-grounded because each piece is done with full attention instead of a slice of one, and the synthesis has to account for all of them — including where they disagree. Same model as the one-window run; different shape around it.

Checkpoint

In your split, was each workstream genuinely doing something different — or four versions of the same look?

Sharpen the division of labour

Add this and run it again:

These workstreams overlap. Redraw them so each one has information or a method the others don't, and tell me which single workstream would change the decision most if it's wrong.

If two workstreams would always agree, they're one workstream. The value is in the parts that can disagree.

One recommendation — built from four passes that actually pulled their weight.

For a big question, how you divide the work is part of the answer. Parallel specialists then a synthesis beats one window doing everything — when the parts are genuinely different.

And the flip side matters: when the task is small, one-shot, or needs a single coherent voice, splitting it just adds overhead. Keep it in one window then.
