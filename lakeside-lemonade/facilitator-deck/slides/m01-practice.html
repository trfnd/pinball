Five habits for briefing a long document.

1

Explain the why. "Visit windows must match the synopsis because sites build their calendars from it." Claude generalizes from the reason.

2

One good example first. Start with one approved sample of house style; models copy examples closely, flaws included.

3

Long material first, question last. Up to 30% better responses in Anthropic's tests with complex documents.

4

Quotes before answers. Ask for the exact passages from the source, then the answer.

5

Permission to say "not stated." Tell it that "not stated in the document" is a good answer.

Anthropic: Prompting best practices · Best practices for prompt engineering

Five habits from Anthropic's guidance, applied to long research documents. 1. Give the why. Anthropic notes Claude "is smart enough to generalize from the explanation," so a reason travels further than a rule. 2. Examples. The docs suggest 3 to 5, but Anthropic's article says start with one, because models copy examples closely, flaws included. 3. Order. Put long documents first and the question last. Anthropic reports up to 30% better responses in its tests, mostly with complex multi-document inputs, so treat that as an upper bound, not a promise. 4. Quote first. Ask for the exact passages before the answer; it's the fastest way to see whether Claude found the right part of the source. 5. Give an out. Permission to say "not stated in the document" reduces made-up filler. The output is still a draft for the responsible author. Ask: "Which of these do you already do? Which will you try this week?"
