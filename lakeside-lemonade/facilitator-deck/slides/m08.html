08 · Skill · Description + Discernment

A Skill is an onboarding guide Claude reads only when it needs it.

What it is: a folder of instructions, plus optional scripts and reference files. Building one "is like putting together an onboarding guide for a new hire."

Test where you know the answer: write three test cases first: one that should trigger it, one that shouldn't, one edge case.

It holds conclusions, not judgment: keep the SOP as the source of truth, name an owner, and re-test when the SOP or the model changes.

Anthropic: Agent Skills · Skill authoring best practices · Improving skill-creator

Anthropic defines Agent Skills as "organized folders of instructions, scripts, and resources that agents can discover and load dynamically." Its analogy suits anyone who has written an SOP: building one "is like putting together an onboarding guide for a new hire." Skills load like a well-organized manual: only the name and short description sit in context until the Skill is needed; then the main file loads, then any extra files. That is Module 02's attention budget in practice. Use prose for flexible guidance, code for exact checks, reference files for look-up. In regulated setups, skills may be off until an admin turns them on. Testing: Anthropic's authoring guidance says "Create evaluations BEFORE writing extensive documentation," starting with at least three scenarios; enterprise guidance asks for 3 to 5 queries per Skill, covering should-trigger, shouldn't-trigger and ambiguous cases. Skill-creator can now run tests and blind comparisons with and without the Skill, because "testing turns a skill that seems to work into one you know works." Anthropic notes "most authors are subject matter experts, not engineers" — this room. Example (ours): a house-style protocol reviewer, tested on past drafts whose issues you already logged. Security: install Skills only from trusted sources, and review even a colleague's Skill before turning it on. Discussion: pairs, 4 minutes. A Skill is like a recipe card: anyone can follow it, but it holds the recipe, not the cook's instincts. Push on ownership: the SOP stays the controlled source of truth; keep the Skill in step with it and re-test when either changes.
